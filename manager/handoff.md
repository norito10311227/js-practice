### A2：A1 を TypeScript に（完了。PR #7）
- `interface GitHubUser { login; name: string | null; public_repos }`、`fetchGit(username): Promise<GitHubUser>`、`res.ok` が false なら `res.status` を含むメッセージで throw、呼び出し側 `main` の try/catch、存在しないユーザーで 404 を確認。

### A3：AniList GraphQL で POST（進行中）
- API：`https://graphql.anilist.co`、POST、`Content-Type` と `Accept` を `application/json`、body は `JSON.stringify({ query, variables: { page: 1, perPage: 25 } })`。認証不要。**現在縮退運転中で毎分30リクエスト**（通常90）。レスポンスは `{ data: { Page: { media: [...] } } }`、失敗時は `errors: [{ message, ... }]`。
- 使っているクエリ（マネージャーが渡したもの。API仕様なので渡してよい扱い）：
  ```graphql
  query ($page: Int, $perPage: Int) {
    Page(page: $page, perPage: $perPage) {
      media(type: ANIME, sort: POPULARITY_DESC) {
        title { native romaji }
        seasonYear
        averageScore
        genres
        studios(isMain: true) { nodes { name } }
      }
    }
  }
  ```
- Jikan API は「繋がらないことが多い」と学習者が報告したため AniList に切り替えた。
- 最後に提出されたコードでできていること：POST の3項目、variables、`res.ok` の確認、`res.json()` を変数に入れてから `json.errors` を確認、`AniListResponse`（`errors?` 付き）、`media` を配列として型定義、`Promise<AniListResponse>`、`main` と try/catch、`main()` の呼び出し。
- **残りのチェックリスト**：
  - [ ] `typecheck` スクリプトを追加し、わざと間違えた行でエラーが出ることを確認
  - [ ] `native` を `string | null`、`seasonYear` と `averageScore` を `number | null` に
  - [ ] throw のメッセージが `json.errors` をそのまま連結していて `[object Object]` になる → `message` を取り出す（1件目 or map + join）
  - [ ] `"Failed to fetch data" + res.status` にスペースがない
  - [ ] `JSON.stringify` での全表示を、`media` を map した `title.native` の一覧表示に置き換え
  - [ ] クエリの `native` を `nativ` に変えて実行し、**2つの throw のどちらが働いたか**を報告させる。AniList は不正なクエリに HTTP 400 を返す可能性が高く、その場合 `res.ok` 側が先に働く。**答えは先に言わない。** 報告を受けてから「GraphQL はエラー時も本文が JSON なので、ok 確認の前に本文を読めば message を表示できる」という設計上のトレードオフを議論する。

## 6. 学習者の傾向（指導方針に反映すること）

- **動くコードは書けるが、なぜ動くか説明できないことがある** → 口頭試問を必ず行う。答えられないときは、読む箇所と思考実験のヒントを出して再回答させる（W1 ではこれで Q2・Q3 が合格した）。
- **実行・型チェックせずに提出しがち**（構文エラー、閉じ括弧・カンマ抜け、`main()` 呼び出し忘れが複数回）→ あなたが実行して確認しつつ、「型チェックを通してから報告」を習慣づける。
- **指摘の一部だけ反映しがち**、前回直した箇所が別の修正で消える（後退）ことがある → チェックリスト形式で、前回との差分を照合する。
- **情報源が多いと混乱する** → 教材1つ、外部ライブラリは無視、課題は小さな段階に分割。
- **管理系の返答（FE予約、研究室アポ等）を先送りしがち** → 期限とデフォルト判断を宣言する。同じ催促を何度も繰り返さない。
- **良い質問をする**（例：「関数の完了時点で fetch は終わっているのに、なぜ呼び出し側で await が要るのか」）→ 実験で確かめさせると理解が深い。
- ユーモアがある（「JS はレジギガスだから」、テスト用ユーザー名に下品な単語）→ 受け流しつつ、公開リポジトリでは中立的な文字列にするよう伝え済み。
- 「いちいち貼るのが面倒」→ Claude Code へ移行した理由。あなたは自分でファイルを読み、実行して確認できる。学習者に貼らせるのは、ブラウザ出力など本当に見えないものだけにする。
