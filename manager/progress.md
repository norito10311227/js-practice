- A4で `practice.js` → `practice.ts` に変換し、W1課題5の関数（`formatWork`、旧 `frameWork`）を `export`、`aniList-fetch.ts` から `import` して再利用。ルート直下の `.ts` でも、`src/` 内の import 元からたどれるため型チェック対象に含まれることを確認済み。
- 最終成果：AniListデータを `{title, year, studio, genre, rating}` に変換 → スタジオ別件数（O(n)、reduceで直接書き換え）→ 平均スコア（null除外、小数第1位）→ タイトル（年）一覧表示。すべて型チェック・実行で確認済み。

### 口頭試問の結果
1. Promiseの3状態・awaitが待つもの：最初「pendingしか分からない」→ ヒントで3状態正解。「awaitはfulfilledを待つ」という誤りは「settle（fulfilledかrejectedか確定）を待つ」に訂正して合格。
2. 404でcatchに行かない理由：最初「json.errorsを受け取るから」と誤答 → ネットワーク成立/不成立の違いを説明 → 自力で「resが成功しているから」に到達。対処法（`!res.ok`でthrow）も自分のコードを見て正答。
3. `number | null` の扱い：A3の実験（`const year: number = "2023"`）と混同 → 実際のケース（`work.year`を`formatWork`に渡す）に絞って再質問 → `as number` で解決したと正答。
4. O(n)版の理由：最初「配列全体をコピーする」と誤答 → 正しくは「集計用オブジェクト（count）をコピーする」だったが、これは自力で訂正して合格。

- 型エラーの原因（`tsc`の`include`範囲、asyncの戻り値がPromiseになる、reduceの初期値の型推論）は、ヒント→自分で試す→再度エラーを読む、のサイクルで毎回自力にたどり着けている。
